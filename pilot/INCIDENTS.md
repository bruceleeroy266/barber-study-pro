## Incident Severity Definitions

| Severity | Definition | Examples |
|---|---|---|
| Critical | System down, data loss, security breach | Site unavailable, database corruption |
| High | Major feature broken, significant user impact | Authentication broken, payments failing |
| Medium | Feature partially broken, workaround exists | Slow performance, minor feature broken |
| Low | Minor issue, cosmetic, no user impact | UI glitch, typo |

---

## Response Times

| Severity | Response | Resolution |
|---|---|---|
| Critical | Immediate | < 4 hours |
| High | < 1 hour | < 24 hours |
| Medium | < 4 hours | < 1 week |
| Low | < 24 hours | Backlog |

---

## Guidelines

1. **Document immediately** — Even if details are incomplete
2. **Update timeline** — Add events as they occur
3. **Be honest about impact** — Accurate user count and duration
4. **Identify root cause** — Not just symptoms
5. **Define preventative action** — Specific measures to prevent recurrence
6. **Share lessons learned** — Help the team improve
