# ASCYN PRO - Pilot Feature Requests

**Purpose:** Track feature requests from pilot users for post-pilot evaluation.

**Note:** No new features will be implemented during the pilot. All requests are logged for future prioritization.

---

## Template

| ID | Date | Requested By | Role | Description | Priority | Pilot Frequency | Recommendation |
|---|---|---|---|---|---|---|---|
| FR-001 | YYYY-MM-DD | Name | Student/Instructor/Admin | Brief description | High/Medium/Low | Daily/Weekly/Monthly | Implement/Consider/Defer |

---

## Priority Definitions

| Priority | Definition |
|---|---|
| High | Critical for user success, blocking workflow |
| Medium | Important for user experience, significant improvement |
| Low | Nice to have, minor enhancement |

---

## Pilot Frequency

| Frequency | Definition |
|---|---|
| Daily | Used every day |
| Weekly | Used at least once per week |
| Monthly | Used occasionally |

## Guidelines

1. **Log every request** — Even if not implementing
2. **Categorize by role** — Student, Instructor, Admin
3. **Assess priority honestly** — Based on user impact
4. **Note frequency** — How often the feature would be used
5. **Make recommendation** — Implement, Consider, or Defer
